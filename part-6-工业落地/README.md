## 一句话简介

前五章讲的是一个 Agent 怎么被造出来，这一章讲它怎么在生产环境里被**管住**。六个问题按依赖顺序排列：这次请求为什么慢、为什么贵（可观测性）？质量怎么被持续衡量（评测）？会被怎么攻击、怎么防（红队）？能不能少花点钱、快点（路由器与成本）？监管要什么（合规）？以及别人是怎么踩坑的——外加一份 30 天上线清单和一张全书知识地图。

## 阅读顺序建议

Ch29 是**地基**：没有 trace 就没有成本归因（Ch32）、就没有线上评测数据源（Ch30）、就没有红队回归基线（Ch31）。Ch30-32 可以乱序读。Ch34 是全书收尾，承载 Part 1→6 的完整知识地图。

## 边界（设计约定）

- 讲**通用要素**，不讲某个监控平台的用户手册。产品名只在"一句话点名 + 抽模式"处出现。
- 合规章节讲**机制**（对工程团队的实质要求），不做法条翻译。
- 案例讲**机制层面的教训**，案例中的具体数字若只有二手来源，必须标明是公开报道口径。
