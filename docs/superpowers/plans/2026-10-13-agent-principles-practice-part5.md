## ⚠️ 0. 单位陷阱（Part 3 教训，必须先读）

Part 3 的 plan 把 spec 的**中文字数**当成了 `wc -m`，整体翻倍，实际产出是预期的一倍。

- **所有字数一律写 `wc -m`，必须带单位。**
- 换算：**中文字数 ≈ `wc -m` ÷ 2**
- **不要为凑数字删内容。** 一·甲 的术语三件套、worked-example、"没有它会怎样"起手本身就吃篇幅（用户已在 Part 3 裁定接受该实况，commit `063ec98`）。
- 本 plan 区间比 spec 朴素估计宽 ~20%，是刻意余量。
- **⚠️ 上限必须留真余量，不要贴着给（Part 4 连续两章教训）。** Part 4 的 Ch17 交付时距上限 24 字符、Ch18 距 1 字符——两次都以「刚好卡住」收尾。这逼着写手为凑数找冗余可砍，即便他们砍的确实是冗余、也没删三件套，**这个过程本身就在制造压力**，而且 Ch17 直接因此产生了 🔴 阻断项。
  **因此：一章交付时若 `wc -m` 与上限差 < 200 字符，视为区间给窄了，下次同类章节加宽。** 可懂性永远优先于篇幅。

## 4. 全 Part 共同纪律

### 4.1 用户禁令（不可协商）

- **绝不执行任何代码文件。** 不跑 `.py`、不 `python3 x.py`、不 `python3 -c "import"`、不 `py_compile`、不 REPL。代码核查只能**人工逐行静态推演**。spec §6 里"抽样 50% 在本地能跑通"这类要求**作废**，改为静态推演。
- **并发不超过 3 个子代理。**

### 4.2 CLAUDE.md 一·甲（最高优先级）

一节新概念 ≤3（超了就分小节）｜直觉→类比→视觉→公式不可颠倒｜同段缩写 ≤3｜一招鲜+其余一句话点名｜worked-example 在前｜图紧贴正文｜每章 1-2 张主图 + 多张局部小图｜冗余覆盖｜**术语三件套（白话+类比+小例子）**｜**每节先演「没有它会怎样」**

Part 5 特别要求：**先流程后代码**（worked-example effect）——代码块前面必须先有文字把这一步"在干什么"讲清楚。

### 4.3 审查范围

**单章只审易读性**：能否一句话转述、术语是否裸用、类比是否到位、图是否贴正文、有没有吸引力。
**事实/链接/代码运行一律不查**，统一推迟 Task 7。

### 4.4 跨章引用与章号基准

- 章内互引 `参见 24.3`；跨 Part 全角 `（见 Part N ChM）`
- **基准**：Part 1 = Ch1-5｜Part 2 = Ch6-10｜Part 3 = Ch11-16｜**Part 4 = Ch17-22**｜**Part 5 = Ch23-28（Ch23 Tool Calling 与 RAG、Ch24 记忆与规划、Ch25 多 Agent 协作、Ch26 Code Execution、Ch27 协议集成）**｜Part 6 = Ch29-34（Ch29 可观测性、Ch30 Evaluation、Ch31 Security 与红队、Ch32 模型路由器与成本控制）

### 4.5 产品中立

正文概念定义位零产品名、零私有命名。**框架名（CrewAI / LangGraph / AutoGen / mem0 / Letta / Zep）只在"一句话点名 + 抽模式"处允许出现**，不做 API 教程（spec §10.4）。Ch28 的"主流产品特性自检表"必须写成**通用要素**清单，不能变成产品横评。

### 4.6 代码规范（Part 5 特别）

- 单文件 ≤ 200 行
- 文件头 3 行：`# runnable: yes|no` / `# depends: <pkg>` / `# usage: python xxx.py`
- 注释中文，说明**意图**而非复述语法
- **正文引用的代码块必须与 `.py` 文件逐字一致**（Task 7 会做 md ↔ .py 对账）

### 4.7 联网核查

CLAUDE.md §十三 要求联网确认，不凭记忆。协议章节（MCP 版本演进、A2A v1.0、x402）时效性极强，**必须 WebSearch 核实**。
⚠️ **ar5iv 陷阱**：核对多版本论文不要用 `ar5iv.labs.arxiv.org`，用 `arxiv.org/abs/<id>`。
⚠️ **不要引用无法核实的链接**（Part 3 有一条 YouTube ID 因无法证实已被替换）。
