## 1. 🚨 spec 的三处问题，本 plan 已裁定（写手必读）

### 1.1 Ch34.1 Klarna 案例：数字有争议，必须降级为"报道口径"

spec 说 Klarna「从 700 FTE 到 hybrid 模式的回滚教训」。**这个叙事流传极广但几乎全部来自二手博客**——spec 自己列的两个来源 `blog.doshby.com` 和 `twig.so` 就是典型的一次性聚合站。

- **写作时不得把二手博客的数字当既成事实写。**
- 凡引用 Klarna 的具体数字（700 FTE、2/3 会话量、2024-02 与 2025-05 两个时间点），**必须标明是公开报道口径**，并给出可访问的一手来源（Klarna 官方新闻稿、CEO 访谈的原始出处）。
- **一句话核心必须落在机制上而不是数字上**：这不是"用了 AI 就会翻车"，而是"**AI-only 取代人工，却没有把人类兜底通道一起设计进去**"——正好接住 34.4 的共性结论。
- Task 7 终审时若找不到一手来源，**该数字直接删掉，保留机制叙述**。

### 1.2 Ch34.2 违反了 CLAUDE.md §一 产品中立

spec 原写「参考 Claude Code / Codex CLI 的 telemetry 实践」——这是 CLAUDE.md 明令禁止的产品命名（§一：不引用某个产品的私有命名；§4.6：正文零产品名）。

**裁定**：改为「**案例二：一个编码 Agent 的 telemetry 实践**」，写成通用要素——它记录哪些 span、怎么把成本归因到工具而不是笼统计到请求、失败样本怎么回流成回归用例。**不点名任何产品，不引用任何私有字段名或遥测字段。**

> 注：这是 CLAUDE.md §一 已知内部张力的一个具体点（覆盖表把真实案例列为必需，而同一节要求产品中立）。本裁定**只解决写法，不改 CLAUDE.md**——是否放宽成文是用户的事。

### 1.3 Ch33 合规：时效性极强，必须联网核实且不得写死日期

EU AI Act 的适用时间表分阶段推进，2026-10 这个时点上的准确状态**必须 WebSearch 核实**，不得凭记忆写。同时：

- **写机制，不写法条翻译**（spec 决策 5 的理由：传统合规标准应让位给专业资料）。

## 4. 全 Part 共同纪律

### 4.1 用户禁令（不可协商）

- **绝不执行任何代码文件。** 不跑 `.py`、不 `python3 x.py`、不 `python3 -c "import"`、不 `py_compile`、不 REPL。代码核查只能**人工逐行静态推演**。
  > **spec §6「所有 Python 代码统一运行」作废**，改为静态推演。
- **并发不超过 3 个子代理。**

### 4.2 CLAUDE.md 一·甲（最高优先级，冲突时永远优先）

一节新概念 ≤3（超了必须显式分小节）｜直觉→类比→视觉→公式不可颠倒｜同段缩写 ≤3｜一招鲜+其余一句话点名｜worked-example 在前｜图紧贴正文｜每章 1-2 张主图 + 多张局部小图｜冗余覆盖｜**术语三件套（白话+类比+小例子）**｜**每节先演「没有它会怎样」**

**Part 6 特别提醒**：这一 Part 的术语全是英文缩写（DORA/OTel/OTLP、LLM-as-judge、OWASP、RAGAS、SOC 2、ISO 42001、FLOPs……），**缩写堆砌是本 Part 最大的易读性风险**。缩写必须全称首现 + 中文译名，RAGAS / OWASP 这类展开时尤其要逐条给白话解释。

### 4.3 审查范围

**单章只审易读性**：能否一句话转述、术语是否裸用、类比是否到位、图是否贴正文、有没有吸引力。
**事实 / 链接 / 代码运行一律不查**，统一推迟 Task 7。（用户原话：「再准确的文章，没有读者又有什么意义。」）

### 4.4 跨章与跨 Part 引用

- 章内互引 `参见 30.4`；跨 Part 全角 `（见 Part N ChM）`
- **基准**：Part 1 = Ch1-5｜Part 2 = Ch6-10｜Part 3 = Ch11-16｜Part 4 = Ch17-22｜Part 5 = Ch23-28｜**Part 6 = Ch29-34**

### 4.5 产品中立（spec §6 自查第 6 条）

正文概念定义位零产品名、零私有命名。**产品名只允许出现在两处**：①「一句话点名 + 抽模式」的位置（Langfuse / Helicone / Phoenix / OpenLLMetry、Not Diamond / Martian / OpenRouter、Promptfoo / PyRIT / Garak、RAGAS / DeepEval）；②本章参考的链接清单。
**不做工具教程**——不写"Langfuse 怎么用""Promptfoo 命令行手册"。

### 4.6 代码规范

- 文件头 3 行：`# runnable: yes|no` / `# depends: <pkg>` / `# usage: python xxx.py`
- 注释中文，说明**意图**而非复述语法
- 正文代码块与 `.py` 文件**逐字一致**（Task 7 做 md ↔ .py 对账）

### 4.7 联网核查（本 Part 强制）

**Part 6 是全书时效性最强的一章**，以下必须 WebSearch 核实，不得凭记忆：

- EU AI Act 分阶段适用时间表、GPAI 义务、$10^{25}$ FLOPs 阈值
- OWASP LLM Top 10 的**当前版本与条目名**
- AIUC-1 的范围与最新版本
- Langfuse / Phoenix 等的量化数据（注明时点）
- Klarna 案例的一手来源

⚠️ **不要引用无法核实的链接。** 优先一手：欧盟委员会官网、OWASP 官网、标准组织官网、公司官方新闻稿。二手博客只能作补充，且必须标明是二手。
